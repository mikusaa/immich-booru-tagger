# Immich Booru Tagger 产品需求

## 产品定位

这是一个独立的 Immich sidecar 服务：从 Immich 官方 API 获取图片预览，在本地运行 ACG/Booru 标签模型，再把标签写回 Immich。它不修改 Immich 核心代码、数据库或原图文件。

## 当前目标

- 为图片生成 WD14 风格的标签，支持选择英文或中文输出，并保留用户已有标签。
- 通过离线词典为英文标签添加中文层级标签。
- 让用户可以限制图库/相册范围，先预览，再小批量写入。
- 以 `auto:processed` 标记成功完成的常规推理，支持增量运行。
- 通过 Docker 和 GitHub Actions 提供可重复部署的 CPU 镜像。

## 功能要求

### 认证与范围

支持单 API Key、多 API Key 和命名账号三种互斥认证方式。处理范围支持图库 include、相册 include 和图库 exclude；相册和图库同时设置时取交集，exclude 优先。没有 include 范围时必须在日志中警告。

### 资产发现

只处理图片，跳过离线、回收站和已删除资产。客户端优先使用 Immich 结构化搜索；旧版本不接受结构化查询时回退到旧分页，并在本地再次校验范围、类型和完成标记。写入前先固定候选快照，避免分页因标签写入而变化。

### 推理与标签

默认后端为 WD14，普通标签和角色标签使用不同阈值，评级标签按评级专用策略处理。标签写入前去重，并通过 Immich 的标签 upsert 接口创建缺失标签。

### 中文标签

词典离线打包，标签路径使用：

```text
属性/<普通标签>
角色/<角色标签>
评级/<评级标签>
```

默认双语输出，中文作为额外标签。设置 `ENGLISH_TAGS_ENABLED=false` 可优先新增中文标签，缺少译名（包括译名被设为空）时写入英文；设置 `TRANSLATIONS_ENABLED=false` 可只新增英文标签，两者不能同时关闭。覆盖项可由用户通过 JSON 文件提供。开关不删除已有标签，旧版 `zh/...` 标签也不会由程序自动删除。

### 写入可靠性

标签关联必须回读确认；确认成功后才写入完成标记。部分写入失败可以重试，成功项不重复写入。状态目录保存失败计数、写入记录和单写入锁。支持 dry-run、失败查询和失败重置。

### 运行与运维

支持单轮、连续、定时、中文补全和仅健康检查模式。提供 `/health` 与 `/metrics`，默认使用上海时区每天 02:00 执行。默认镜像以非 root 用户运行，模型与状态通过卷持久化。

## 非功能要求

- Python 3.11，默认镜像为 `linux/amd64` CPU 版本。
- 请求具备有限重试和退避，避免持续压垮 Immich。
- API Key 不写入日志和状态文件；账号状态用服务地址与 Key 摘要隔离。
- 配置错误、词典错误和模型初始化错误应在写入前失败。
- 自动化测试覆盖配置、范围、回退、写入确认、中文补全、失败状态和健康服务。

## 当前范围之外

- 视频推理。
- 修改 Immich UI 或后端。
- 自动删除图片或自动回滚标签。
- 在线翻译服务。
- ARM64、CUDA 和经过真实验收的 DeepDanbooru 发布镜像。
- 自动替用户整理或删除旧标签。

## 验收标准

1. 使用 dry-run 能看到所选语言的待添加标签，Immich 与状态目录不产生写入。
2. 小批量实际运行后，Immich 中能看到所选语言的标签，已有标签和完成标记保留。
3. 重复运行不会重复创建或关联相同标签，已完成资产会跳过。
4. 配置图库/相册范围后，不会处理范围外资产；旧 API 也不会因回退而扩大范围。
5. 关联回读失败时不会添加完成标记，下一轮可以补齐缺项。
6. GitHub Actions 能通过测试、构建离线冒烟镜像，并在非 PR 事件发布 GHCR 镜像。

## 中文进度与持久化任务

正式任务保存到 `state/progress.sqlite3`，固定候选队列后可跨重启续跑；扫描中断从头核对、去重，不复用不稳定的分页游标。每张结果与失败计数原子提交，任务级故障保留队列。定时服务默认启动恢复兼容未完成任务；新任务仍遵守既有调度配置。日志每 10 秒输出中文阶段及进度，健康接口共享状态快照；旧版进程内计数不再作为持久进度来源。预览不写状态，健康模式不创建或恢复任务。
